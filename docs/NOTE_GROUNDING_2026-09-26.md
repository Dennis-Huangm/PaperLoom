# 长报告整合前的摘录定位

本阶段承接 SVGenius 长文评估中的自由摘录抄写失败。改动位于正式
`ReportGenerator.generate` 的分片笔记到最终整合之间，不要求手工修改报告，
不增加生产流程的模型调用次数。

## 程序行为

分片笔记中旧式 `[[证据:...]]` 先与当前 PDF 物理页面文本匹配。允许的变化仅为
Unicode NFKC 和空白归一化；不会补省略号、改标点、重排行列或跨页拼接。
20–600 个非空白字符的摘录须在全部页面中只出现一次。同页重复也不自动选择位置。
Unicode 映射不能精确还原字符范围时保守地不转换。

成功匹配的摘录转换为 `Q1-页面文本哈希前缀-物理页-起始偏移-结束偏移` 引用。
该范围只包含被核对的摘录，不扩大到相邻模型或其他数值。原来的 S1 固定窗口保持不变；
Q1 是补充格式，不把任意未知 S1 ID 解释为合法范围。定稿时根据当前完整页面文本
重新校验哈希、页码、范围和长度，再取回实际原文。摘要回退、无 PDF、过期哈希和
越界范围不能生成可信页码链接。

无法唯一定位的分片摘录在送入整合前标为依据不可用，原始分片响应仍保存在原调用记录
或已有恢复缓存中。程序不会把近似匹配标成已核实。最终提示明确要求沿用提供的 ID，
不再同时要求模型重新抄写这些原文。历史报告的旧式摘录定位仍兼容，严格程度不降低。

精确摘录与原有固定窗口共用 32,000 字符预算、公式优先和页面轮换分配规则。
整合提示变化自然使旧整合缓存失效；分片提示未变，可以继续复用符合原缓存契约的响应。
引用中的模型、任务、指标与结论是否相符仍需另行核对；字符匹配不是语义证明。

## 一次真实整合结果

本轮只新增 1 次请求，使用用户指定的 `gemini-3.8-flash-high`；服务响应模型名仍为
`gemini-3.8-flash`，不据此独立确认底层身份。8 次分片均重放原结果，未调用图片解释或
外部同步。密钥只用于进程环境，未保存到代码、配置或评估产物。

原始输出共 130 次 ID 引用、0 次旧式自由摘录。去重后 58 条引用全部能定位，19 条
来自精确摘录范围；逐一独立检查其页内原文切片，并确认全部引用 ID 在本次整合清单中。
CCR/rMSE 分别直接引用物理第 18/19 页公式；原文位置和公式仍与上一轮核对一致。

审阅发现数值审核会把无空行的相邻列表项当成一个块，使某项可能借用另一项的引用。
三个失败回归分别覆盖无序、有序和嵌套列表，修复后逐项隔离，数值审核版本升至 2。

模型数量 22 所附局部来源不含总数、部分数值的 PDF 提取连字/单位仍触发提示。
