# 架构改进记录：2026-09-16

本轮按阅读状态、排队任务、论文数据、依赖管理的顺序落实先前审查建议。业务规则沿用收藏与“不相关”互斥；版本规则经用户确定为：历史推荐保留原版本，直接输入无版本 ID 查询最新，显式版本号严格匹配。

## 1. 阅读状态

`reading_state.py` 是状态变更 module，锁与持久化细节收敛在其 interface 后。`library.py` 和 `feedback.py` 保留原有收藏、反馈及评分功能。

- 同一研究方向的读取、保存、取消、负反馈和切换由线程锁及文件锁协调。
- 收藏与负反馈保存在同一 JSON 文档中，一次原子替换完成互斥状态转换。
- `toggle` 包括“判断当前状态”在内的整个操作均在锁内执行。
- 页面补全条目前比较原条目与当前条目，已删除、已标为不相关或已重新保存的条目不被旧补全结果覆盖。
- 保留首次收藏时间、研究方向隔离、幂等删除与最近 30 条正样本规则。

迁移采用首次修改时导入旧文件。新的 `reading-state-<方向ID>.json` 成为唯一权威状态；两个旧文件原样保留。旧数据冲突时比较最后更新时间，同一时间或均无时间时保留负反馈。损坏的新状态文件会报错，不会当作空状态覆盖。

旧版本程序和直接操作旧 JSON 的外部脚本无法参与新的协调机制。启用修改前应结束旧进程并重启；迁移后若回退程序，需要先把最新状态转换为旧格式，不能依赖已经停止更新的旧文件。

Windows 文件锁允许锁定 EOF 之外的字节，因此不需要有竞争风险的锁文件内容初始化。实现依据：[Microsoft `_locking` 文档](https://learn.microsoft.com/en-us/cpp/c-runtime-library/reference/locking?view=msvc-170)。验证已覆盖独立 Windows 子进程；其他操作系统的文件锁分支未在本机执行。

## 2. 排队任务

`web_jobs.JobContext` 在提交时复制配置。报告、每日推荐、周报、版本检查、引用地图和 Obsidian 同步均使用该上下文，运行时不重新读取活动方向。

去重 identity 由任务类型、操作参数、项目路径和配置产生，展示文字不再承担去重职责。历史报告还在提交时捕获所选快照，因此排队期间推荐文件改变也不会改变任务意图。关闭应用时取消尚未分派的任务，已运行任务完成后释放自己的客户端。

新报告目录包含方向和版本，周报、引用地图、版本差异报告也采用方向专属路径。已有产物仍通过原目录遍历方式发现。这里保证的是提交配置与所选论文快照，不是冻结运行时的所有文献库内容或环境变量。

## 3. 论文数据选择与补全

`paper_data.py` 集中本地查找、缓存、ID/版本匹配和失败恢复。Web 与流水线使用同一个本地查找 interface，arXiv 与 alphaXiv 保持各自的 adapter。

| 阅读意图 | 行为 |
| --- | --- |
| 从历史推荐生成 | 按方向、日期和版本获取该条快照，在提交时固定 |
| 从文献库生成 | 使用已收藏记录的版本 |
| 直接输入无版本 ID | 查询 arXiv 当前数据；失败时选择可用的完整本地数据并注明未确认最新 |
| 输入指定版本 | 缓存、快照和外部返回都必须匹配该版本，不以其他版本替代 |

已知版本的元数据、PDF 和 HTML 配图使用同一修订版。历史记录没有可靠版本号时，页面会要求改用直接输入 ID 或指定版本，避免声称保留了无法确定的历史版本。

在 hybrid 发现中，过期完整缓存仍保留为补全失败后的恢复候选。批量补全超时或未返回某篇论文时，不再仅因缓存过期而将它降为预览。manifest 单独记录 `cached_fallback`，推荐/报告保留对应说明。alphaXiv 的独立召回和发现来源记录继续保留。

## 4. 依赖装配与生命周期

`ResearchClients` 管理研究任务实际使用的客户端、解析器和报告生成器，使用时才创建。流水线、研究方向生成、周报、版本检查及 Obsidian 可以接收外部传入的依赖集合。

- 默认创建的网络客户端在执行作用域结束时关闭，异常路径也会关闭。
- 外部注入的 adapter 仍由调用方管理，借用它的任务不会擅自关闭。
- 核心测试通过正常构造函数和可注入依赖运行，移除了原有 `__new__` 构造绕行。
- 未引入 DI 框架、数据库或新的安装依赖。

这些改动提高了 depth：复杂性留在有实际职责的 module 内。seam 位于阅读状态变更、任务提交、论文数据选择与依赖所有权上；调用方获得 leverage，维护和测试获得 locality。不是所有第三方集成的短生命周期调用都在本轮统一改写，性能与内存占用也没有进行基准测量。
