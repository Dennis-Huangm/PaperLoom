# 研究方向检索生成：明确条件语义、可编辑草稿与可验证召回

## Problem Statement

用户通过关键词、描述和参考论文创建研究方向，希望系统持续发现相关论文。目前生成结果直接保存并可立即启用，但用户难以看出系统如何理解方向、哪些条件会直接淘汰论文，也无法在启用前验证生成结果。

现有行为存在以下可由代码确认的问题：

- 模型生成的列表可以覆盖用户输入，包括把用户填写的负向关键词替换为空列表。
- 概念组的提示语表达“必须同时满足”，执行规则却是模型生成的最低命中组数。字面匹配不足会在模型精排之前淘汰论文。
- arXiv 服务端将查询短语全部用 OR 连接，按投稿时间取有限候选；宽泛词可能占用候选额度，后续排序无法找回未被取回的论文。
- “排除关键词”实际只影响排序，无法表达明确排除；直接把负向词升级为硬过滤又会误杀仅在背景介绍中提及该词的论文。
- 只提供参考论文、未启用模型时，生成结果可能只剩类别和日期约束。参考元数据获取失败也没有形成清晰的草稿质量状态。
- 创建时缺少预览、试搜和主题规则检查；已有设置编辑与推荐后的筛选审计不能替代创建时的验证。

影响包括漏掉相关论文、混入偏题论文、生成条件与用户意图不一致，以及故障时把不完整结果误认为可用配置。上述影响尚未通过线上数据量化，本规格不预设召回率提升幅度。

## Solution

创建研究方向改为“输入意图 → 生成可编辑检索草稿 → 可选试搜 → 保存并按需启用”。用户可以跳过试搜；草稿只要通过必要校验即可启用，信息不足的草稿则清楚说明如何补全。

默认遵循三个已确认原则：候选阶段偏向少漏、最终推荐偏向准确；用户明确指定的约束优先于模型建议；普通关键词首先是主题线索，不自动成为必要条件。

草稿以普通语言展示研究主题、必要条件、提高或降低优先级的偏好条件、明确排除条件、同义表达和参考依据。高级展开区展示类别、查询分支及预算。用户可逐项调整，模型提出的修改不能静默改写用户约束。

生成器先整理研究意图，再形成可执行检索方案。检索方案使用少量有明确用途的查询分支，在固定总预算内分别取候选并合并去重。参考论文主题检查和可选试搜使用与正式推荐一致的主题判定规则，并展示通过、排除或待判断的原因。

## User Stories

1. As a 研究者, I want 通过关键词、描述或参考论文表达研究问题, so that 系统理解我要寻找的工作。
2. As a 研究者, I want 普通关键词默认作为主题线索, so that 我不会因为列举了多种技术路线而意外要求论文同时覆盖所有路线。
3. As a 研究者, I want 明确标记必要条件, so that 最终推荐满足我真正不可缺少的要求。
4. As a 研究者, I want 分别表达提高和降低优先级的偏好, so that 相邻工作仍有机会进入候选。
5. As a 研究者, I want 单独设置明确排除条件, so that 不符合研究范围的论文不会进入最终推荐。
6. As a 研究者, I want 系统区分论文主题与背景中的提及, so that 相关论文不会因一个负向词而误被排除。
7. As a 研究者, I want 用户输入与模型扩展分开显示和保存, so that 我知道每条条件从何而来。
8. As a 研究者, I want 模型保留我的显式条件并把修改作为建议, so that 自动生成不会改变我的研究边界。
9. As a 研究者, I want 检查系统归纳的研究问题, so that 我能在启动每日推荐前修正理解偏差。
10. As a 研究者, I want 在草稿中编辑条件及同义表达, so that 不必手动修改配置文件。
11. As a 研究者, I want 重新生成时保留已确认的用户修改, so that 改善某部分不会撤销其他决定。
12. As a 研究者, I want 查看参考论文的解析状态及采用依据, so that 我知道哪些参考材料实际参与了生成。
13. As a 研究者, I want 只提供参考论文也能建立草稿, so that 我不必预先掌握准确的检索术语。
14. As a 研究者, I want 元数据或模型不可用时看到具体缺失项, so that 我能补关键词、重试或保留草稿。
15. As a 研究者, I want 用参考论文检查主题规则, so that 能发现生成条件连参考工作都无法解释的矛盾。
16. As a 研究者, I want 参考论文检查忽略每日日期窗口, so that 经典论文也能用于检查研究方向。
17. As a 研究者, I want 按需试搜并查看有限样本, so that 能在启用前检查方向是否过宽或过窄。
18. As a 研究者, I want 看到候选来自哪条查询以及为何通过或被过滤, so that 调整条件有明确依据。
19. As a 研究者, I want 看到零结果、部分来源失败和检索额度用尽的区别, so that 不会把系统限制误解为没有相关论文。
20. As a 研究者, I want 跳过试搜并启用有效草稿, so that 创建简单方向仍然快捷。
21. As a 研究者, I want 保存草稿而不改变当前研究方向, so that 日常推荐能够继续运行。
22. As a 研究者, I want 试搜不改变阅读状态、历史已推荐记录或调度配置, so that 预览没有正式推荐的副作用。
23. As a 研究者, I want 常见词形、缩写和连字符变体被合理处理, so that 表达差异不会导致不必要的漏检。
24. As a 研究者, I want 核心主题保有独立的候选额度, so that 宽泛的相邻查询不会占满结果。
25. As a 研究者, I want 多条查询中的重复论文合并但保留来源, so that 推荐和解释保持清晰。
26. As a 研究者, I want 已有研究方向继续按原规则运行, so that 更新功能不会悄悄改变长期使用的条件。
27. As a 研究者, I want 旧档案转换为新草稿时看到条件变化, so that 可以自行选择是否采用新的语义。
28. As a 研究者, I want 近期关注点继续服从研究方向边界, so that 收藏引导不会越过必要条件或明确排除条件。
29. As a 研究者, I want 模型不可用时仍能看见条件判断的不确定性, so that 系统不会把无法验证的论文当作满足条件。
30. As a 维护者, I want 用固定论文样本验证生成与推荐行为, so that 修改模型提示或检索策略后能够发现质量回退。

## Implementation Decisions

### 1. 领域语义与输入来源

- 使用现有“研究方向、基础检索、定向检索、近期关注点”等领域用语，并增加主题线索、必要条件、偏好条件、明确排除条件、检索草稿和试搜。
- 普通正向关键词属于主题线索，现有“不感兴趣的方向”输入默认属于降低优先级的偏好。新增显式交互表达必要条件和明确排除条件。
- 用户在自由描述中表达的强约束应提取为可见条目；存在歧义时作为待确认建议。不得仅凭模型推断创建已经确认的硬约束。
- 每个条件有稳定身份、语义类型、用户或模型来源、原始表达、用于匹配的别名及确认状态。模型建议需有简洁的依据说明；依据可指向用户输入或成功解析的参考论文，不要求泄露模型内部推理。
- 用户修改后的内容归为用户来源。重新生成只替换模型建议，保留用户条目、显式删除及已确认约束；冲突作为可见建议或校验错误处理。
- 参考论文是方向归纳的证据，不意味着论文中的所有方法、数据集或应用场景都成为必要条件，也不意味着参考论文必然是最终推荐的正例。

### 2. 草稿生成与校验

- 沿用 ProfileGenerator 的研究客户端注入边界，生成输出改为包含状态和诊断的草稿。ProfileManager 负责草稿及已启用档案的读取和持久化；Web 层保持请求编排职责。
- 模型负责提出主题解释、条件建议、别名及查询分支建议；确定性代码负责校验、保留用户约束、分配预算、编译查询和生成最终持久化结构。模型不直接决定任意数值门槛或请求额度。
- 校验输出类型、非空主题依据、条件类型、重复项、长度与数量上限、类别合法性、引用是否来自已提供的参考材料，以及用户约束是否被完整保留。不得通过把任意对象转为字符串来接受非法字段。
- 既有输入上限继续生效；超过上限和被截断的内容必须有可见提示。不得在校验时静默丢掉必要条件或明确排除条件。
- 生成状态至少区分可启用、需要补全、生成失败。参考资料部分缺失是独立诊断：主题依据仍然充足时允许启用，并显示缺失信息。
- 无模型时可从明确的用户词建立可解释的基础草稿；只有参考论文而不能可靠归纳主题时保存为需要补全。类别和日期本身不构成充分主题依据。
- 模型请求失败、格式错误、参考论文全失败分别记录原因，保留用户输入并支持重试。不得静默切换成类别级检索并标为生成成功。
- 新档案使用明确的应用默认设置和用户此次输入，不复制当前活动方向的主题条件。共享运行设置可以沿用，但需要区分其来源；旧方向独有的类别、词表和门槛不能成为静默回退值。

### 3. 草稿生命周期与交互契约

- 生成只创建草稿，不修改活动方向。草稿可编辑、保存、重新生成、检查参考论文、试搜和启用；试搜不是启用前置条件。
- 页面首先展示研究主题与条件含义，查询语法和预算放在高级区域。主要动作采用“保存草稿”“试搜”“保存并启用”等用户可理解的名称。
- 草稿带有修订标识；修改后旧试搜结果显示为过期。启用必须针对用户看到的最新有效修订，校验失败或陈旧提交不改变活动方向。
- 创建、编辑和启用保持现有方向隔离与陈旧页面保护。正式调度只读取已启用或已配置的正式档案，不读取未启用草稿。
- 请求与响应明确草稿标识、修订、生成状态、条件来源、诊断及允许的后续动作。试搜接受特定草稿修订，返回有限样本、来源统计和原因；重试不得意外创建多份正式方向或启用旧结果。
- 参考元数据缓存可由预览复用，但试搜不得写入阅读状态、已推荐集合、正式推荐快照或发送通知，也不得修改调度与活动方向。

### 4. 检索组织与匹配

- 基础检索最多包含三条有明确用途的分支：核心主题、主题与场景组合、相邻方法扩展；没有充分依据的分支不生成。相邻分支必须有主题锚点，避免单独以 AI、LLM 等宽泛词启动检索。
- 分支使用结构化概念组表达组内同义、组间组合，由 arXiv 适配层安全编译为查询，避免把模型输出直接当成原始查询语法。
- 基础检索沿用现有总候选预算；多分支不能把预算按分支数放大。核心分支至少分得一半额度，其余额度在其他分支间确定性分配；预算小于分支数时优先核心并减少分支。单一分支使用全部预算。
- 每个分支保持既有类别与日期限制，记录请求额度、返回数量及是否触及上限。首次版本不增加无界翻页或自动扩窗；不足的额度不触发无界补搜。
- 合并按论文身份去重，保留所有检索来源和分支。继续沿用完整元数据优先、版本处理及来源合并规则。
- 近期关注点的定向检索继续独立补充基础检索，使用既有独立限额；不得削减基础检索额度或绕过方向边界。面向用户报告时区分基础和定向的预算。
- 匹配统一处理大小写、空白、常见连字符形式；使用受控的词形与缩写别名。上下文不明确的缩写和可能改变意义的词干扩展作为建议，不自动制造匹配。
- 新语义下，模型生成的普通主题线索和偏好不再通过“至少命中 N 组”的隐式硬门槛提前淘汰论文。它们参与候选排序及语义相关性判断；显式必要条件和明确排除条件单独判定。
- 条件判定返回满足、不满足或无法判断，并附可定位到题名、摘要或结构化元数据的依据。没有字面命中不能直接证明语义必要条件不满足；提及排除词也不能直接证明论文主题属于排除方向。
- 可确定的属性条件可直接执行；语义条件复用模型精排阶段进行有依据的判定。普通词匹配只作为证据和排序线索。语义无法判断的候选保留在预览或审计中，不能被当作已满足硬约束进入最终推荐。
- 模型或元数据不足时，明确标记无法判断；可以产生较少的最终推荐并提示原因，不能为了凑够推荐数自动放宽用户硬约束。无硬约束时沿用可解释的本地排序降级。

### 5. 参考检查、试搜与解释

- 对成功解析的参考论文执行同一套主题及约束判定，忽略每日日期窗口和历史已推荐状态。展示通过、冲突或无法判断；不得为了让所有参考通过而自动修改用户条件。
- 参考论文检查验证局部规则一致性，不等于在线召回率或精确率评估。未提供参考论文不阻止有效草稿启用。
- 试搜采用正式检索、合并、条件判定和排序逻辑的同一入口或共享编排，使用明确的小预算，不另写一套简化语义。试搜复用既有任务执行设施和外部请求限流。
- 默认展示最多十篇最终候选和最多十篇被过滤或待判断样本，并提供阶段总数；显示生成时间、草稿修订、来源状态、限额及未完成的判断。
- 区分无检索结果、主题过滤后为空、硬约束无法验证、来源失败及部分成功。触及额度上限仅说明结果有限，不能声称所有匹配论文已取回。
- 推荐后的筛选审计继续保留，增加条件身份、判定依据及检索分支，以便从最终结果回溯草稿中的规则。

### 6. 兼容性与交付顺序

- 为新检索计划增加显式格式版本。旧档案继续使用旧字段和旧执行语义，不在加载时把负向关键词升级为硬排除，也不自动移除用户曾配置的概念组门槛。
- 用户可以把旧档案复制为新草稿，查看旧门槛与新条件的变化后再启用；转换不覆盖原档案。旧档案中无法推断来源的字段明确标为历史配置。
- 设置编辑、手工运行和多方向调度均按档案版本使用同一解释规则，避免设置页仍能写入与新条件相矛盾的旧门槛。
- 第一阶段交付条件语义、用户约束保留、有效性校验和旧档案兼容；第二阶段交付草稿编辑、参考检查与可选试搜；第三阶段交付分支检索与固定样本验证。完整验收需覆盖所有阶段。

## Testing Decisions

- 优先使用最高的现有可测试边界：通过本地 Web 应用的真实 HTTP 路由完成生成、编辑、试搜、启用，再通过现有推荐入口检查可观察的候选、推荐和审计结果。
- 只替换 ResearchClients 中的外部模型、arXiv 和 alphaXiv 适配器；真实执行生成解析、校验、存储、配置装载、检索编排和筛选。不得像现有创建页面测试那样替换整个生成器来验收本功能。
- 测试验证用户可见结果、持久化副作用和外部服务契约，不锁定提示词全文、内部辅助函数数量或无关调用顺序。运行速度需要时，补充少量 DiscoveryService 和 arXiv 请求边界测试，不增加另一套产品入口。
- 复用现有 Web TestClient、临时目录档案测试、发现服务假客户端、推荐筛选审计测试和近期关注点回归测试的写法。所有默认自动化测试离线、固定数据、固定时间。
- 用户已确认采用上述现有集成边界。真实浏览器自动化不是本规格的默认前置条件，页面布局和中文解释需在交付时人工或工具检查。

验收场景：

1. 输入三个主题线索，模型将它们建议为三个必要条件：草稿保留为未确认建议，不自动启用三个硬门槛。
2. 用户输入必要条件和负向偏好，模型返回缺失、空列表或相反意见：原始条目完整保留，冲突可见。
3. 用户编辑或删除模型建议后重新生成：已确认用户改动不丢失，明确删除的建议不会无提示复活。
4. 畸形 JSON、错误字段类型、非法类别、超限或伪造参考依据：不能写成可启用的正式方向，用户输入保留且诊断具体。
5. 普通相关论文只采用受支持的词形或连字符变体：不会仅因表达差异被普通主题线索硬过滤。
6. 论文背景提及负向主题、正文研究目标属于目标方向：仅提及不构成明确排除；真正以排除主题为研究对象的样本被排除并有依据。
7. 必要条件无法从现有元数据验证，且模型不可用：候选可见且状态为无法判断，不伪装为满足条件进入最终推荐。
8. 多个候选仅满足偏好条件的一部分：仍可进入相关性评估，不执行隐式“全部偏好必须命中”。
9. 只提供参考论文且解析成功、模型可用：生成有主题依据的草稿，并记录所用参考材料。
10. 只提供参考论文但无法归纳主题，或全部参考解析失败：可保存需要补全的草稿，不能启用类别级空主题检索。
11. 参考资料部分失败但用户关键词足够：生成可启用草稿，并显示具体缺失资料；无模型时的基础草稿状态准确。
12. 参考论文早于检索日期窗口：主题检查仍执行；参考与用户硬约束冲突时展示冲突，不自动放宽条件。
13. 生成、编辑、试搜均不改变当前方向；只有有效且修订一致的启用请求能够改变活动方向。
14. 编辑草稿后查看旧试搜：结果显示过期；陈旧启用请求或跨方向误提交被拒绝且不写入错误方向。
15. 跳过试搜可启用有效草稿；阻塞性校验失败时不能启用，并给出明确补全操作。
16. 试搜前后比较阅读状态、已推荐集合、调度与通知记录：均无正式运行副作用；允许缓存和独立预览结果变化。
17. 多分支返回重叠论文：合并后唯一且来源完整；请求额度总和不超过预算，核心额度和低预算行为符合约定。
18. 宽泛分支返回满额，核心分支返回相关论文：核心候选不被宽泛分支挤掉，触顶状态可见。
19. 部分来源失败、全部失败、零结果、过滤后为空：呈现不同状态，不将失败报告为成功零结果；现有限流和失败回退仍生效。
20. 近期关注点补充与基础检索命中同一论文：合并去重保留路线，所有候选最终服从相同用户硬约束。
21. 旧档案加载和运行：旧负向词及概念组门槛行为保持；复制为新草稿不覆盖旧档案。
22. 新版档案经过设置页保存、手工运行和定时任务：条件含义、来源及硬约束行为一致。
23. 两个研究方向连续生成：新方向没有继承前一方向独有的类别、词表或概念门槛。
24. 最终推荐不足目标篇数：输出实际结果及原因，不为补足数量放宽硬约束。

质量验证使用固定正例、相邻工作、背景提及负向词、真正排除主题和表达变体样本；分别记录候选覆盖、最终相关性和错误排除。参考论文自检不是完整基准。联网抽查作为可选验收证据，记录查询时间和限额，不进入默认自动化测试；在取得数据前不声称量化提升。

## Out of Scope

- 更换模型供应商、训练嵌入模型、搭建向量数据库或全量论文索引。
- 重做本地全文搜索、阅读状态、报告生成、投递和收藏反馈系统。
- 无界分页、无限重试、自动扩大日期或类别范围，以及为了凑推荐数放宽明确约束。
- 自动迁移并覆盖所有历史档案，或让模型自行启用未经用户查看的方向。
- 根据单次试搜或参考论文自检宣称完整召回率，或预设未经测量的质量收益。
- 把完整浏览器自动化套件作为首轮规格的强制依赖。

## Further Notes

- 用户已同意候选阶段偏向少漏、用户约束优先、草稿预览与可选试搜的建议。本规格把其余可逆实现选择写为默认方案，避免继续开展需求访谈。
- 典型场景：“世界模型、具身智能、视频预测”是三条主题线索；只有用户明确选择“必须用于具身场景”后，该要求才成为必要条件。视频预测仍可只是偏好路线。
- 明确排除针对论文主题或属性，其证据标准应与必要条件保持一致；已存在的单篇论文不相关标记继续按原阅读状态规则执行。
- 实施完成时应交付可编辑草稿、可选试搜、统一条件判定、旧档案兼容、查询分支及上述验收证据。本文本是功能规格，不表示优化已实现。
