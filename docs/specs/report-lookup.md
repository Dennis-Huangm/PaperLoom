# 统一指定版本的报告查找，保留现有选择语义

## Problem Statement

研究者需要从推荐、收藏库、报告总览和收录入口访问正确研究方向、正确指定版本的阅读材料，也需要周报、论文比较与知识库导出使用符合各自用途的报告。

当前报告目录读取、身份匹配、材料可用性和优先级分散在多个 module。网页依赖 HTML，证据读取依赖 Markdown；收录指定报告时还会重复查询目录。维护者修改报告规则时必须跨多个调用方核对，容易让网页所展示的材料与下游读取行为发生意外变化。

本次确认的是架构维护成本与重复查询，并未证明现有优先顺序存在功能错误，也未通过性能基准证明目录扫描构成瓶颈。不同用途的材料要求与选择顺序是需要保留的兼容行为。

## Solution

深化现有报告读取 module，集中报告目录发现、元数据读取、身份匹配及材料事实，使网页与阅读材料调用方复用这些事实。保留用途相关的选择政策：网页选择可展示的 HTML，证据读取选择可用的 Markdown，显式选择报告时始终尊重用户所选报告。

本轮是保留行为的重构。用户已确认不统一各用途的排序政策，不改变持久数据格式，不增加持久缓存；先消除单次报告解析中的重复目录查询。

## User Stories

1. As a 研究者, I want 打开推荐快照对应指定版本的报告, so that 阅读材料不会被其他修订版替换。
2. As a 研究者, I want 收藏库展示当前研究方向可用的报告, so that 不会意外使用另一方向的专属材料。
3. As a 研究者, I want 继续访问无方向标记的历史报告, so that 既有资料无需迁移即可使用。
4. As a 研究者, I want 已知版本缺少报告时保持缺失状态, so that 未知版本不会被误认为匹配材料。
5. As a 研究者, I want 未知版本遵循现有精确匹配规则, so that 系统不会自行猜测修订版。
6. As a 研究者, I want 同版本的方向专属报告继续按现有规则优先, so that 重构不改变研究方向语境。
7. As a 研究者, I want 同等方向匹配的报告继续按现有质量等级选择, so that 完整报告与摘要级报告的区别得到保留。
8. As a 研究者, I want 网页自动选择报告时保留现有日期与生成时间顺序, so that 熟悉的默认阅读入口不会变化。
9. As a 研究者, I want 证据读取保留现有 Markdown 修改时间的决胜规则, so that 周报和比较不会因重构换用其他材料。
10. As a 研究者, I want 网页只呈现满足当前 HTML 可用性要求的报告, so that 不会把仅有 Markdown 的材料误显示为可打开的网页。
11. As a 研究者, I want 下游证据读取继续接受仅有 Markdown 的报告, so that HTML 缺失不会使可用证据无故消失。
12. As a 研究者, I want 显式收录一份历史报告时使用我选择的那一份, so that 更新或质量更高的其他报告不会替换我的选择。
13. As a 研究者, I want 收录时报告与 PDF 仍属于已解析的材料来源, so that 不会在重复查找中混入另一份报告的附件。
14. As a 研究者, I want 选中报告缺失或版本不匹配时保留明确错误, so that 系统不会静默改选其他材料。
15. As a 研究者, I want 相关材料在收录前消失时仍得到既有失败或未完成结果, so that 已读取的目录信息不会被当作写入成功证明。
16. As a 研究者, I want 报告总览继续按论文归组并展示相关研究方向, so that 跨方向浏览能力保持可用。
17. As a 研究者, I want 总览代表报告继续遵守其现有版本和质量优先级, so that 总览政策不被单方向读取政策替代。
18. As a 研究者, I want 周报只使用符合原有截止时间规则的报告, so that 历史总结不会纳入未来材料。
19. As a 研究者, I want 损坏元数据继续受到现有容错规则约束, so that 合法报告不因重构失去可见性。
20. As a 研究者, I want 下一次操作能发现新生成或已删除的报告, so that 临时复用不会造成跨请求陈旧结果。
21. As a 维护者, I want 报告身份与材料读取集中在一个 module, so that 修改规则时具有更好的 locality。
22. As a 维护者, I want 通过现有读取和用户操作 interface 验证重构, so that 测试能够承受内部 implementation 调整。

## Implementation Decisions

- 深化现有 report_store module，作为共同报告事实的所有者；web_catalog 保留浏览器展示数据转换，Web 与收录入口负责其交互语义。核心报告读取不得反向依赖 Web module。
- 共同事实涵盖报告元数据、论文身份、研究方向、指定版本及 HTML、Markdown、PDF 的路径与可用性。具体内部结构由实施者决定，不引入泛化存储框架或新的外部 adapter。
- seam 优先沿用现有报告读取与高层用户操作 interface。保留既有调用兼容性；内部变化不要求全部调用方理解目录布局或重新实现身份判断。
- 方向匹配保留现有默认方向及无方向标记的 legacy 语义。已知版本不得退回未知或不同版本，未知版本也不推断为其他已知版本。
- 不把不同用途的政策合并为一个全局“最佳报告”。方向内网页默认选择、Markdown 证据读取、跨方向总览及指定报告解析分别保留现有政策，但共享共同事实。
- 方向内网页默认选择继续按方向专属性、报告质量优先；同级时保留现有目录输出顺序，即日期、生成时间或既有更新时间回退的排序。不新增全局排序决胜条件。
- Markdown 证据读取继续按方向专属性、质量、Markdown 修改时间以及现有最终决胜顺序选择。周报的生成时间、日期回退、时区和截止时间处理保持不变。
- 跨方向总览继续按当前版本、质量、HTML 修改时间选择代表报告，保留方向汇总、报告次数与展示排序。不得套用方向内匹配规则收窄总览。
- 指定报告解析以显式报告身份为准，并保留论文身份、请求版本和来源校验；不因有更新或更高质量报告自动换选，也不额外引入当前方向过滤改变现有显式选择行为。
- 报告目录与证据读取的材料要求分别保留。不得为共享实现而要求每份报告同时具备 HTML、Markdown 和 PDF。
- 单次指定报告收录流程复用同一次解析得到的元数据和材料路径，避免先解析论文后再次扫描目录查找同一报告。复用范围限于当前操作，不能形成进程级或跨请求缓存。
- 读取结果不构成文件事务快照，也不替代收录执行阶段的材料验证。文件消失、失效或指定材料不可用时，沿用当前错误和同步回执语义。
- 持久目录布局、元数据格式、报告身份、链接、现有错误状态和用户数据保持兼容。不改变报告生成、发布、删除的锁与生命周期契约。
- 本轮不扩展元数据修复或身份规范化规则；遇到未覆盖的异常情况，先查清既有行为，避免借重构静默扩大兼容范围。

## Testing Decisions

- 用户已接受沿用现有报告读取、网页与收录流程验证，以及同版本多报告、材料缺失、历史方向兼容、周报截止时间和指定报告收录的验收范围。
- 好的测试跨调用方实际使用的 interface 断言选择结果、展示结果、导出内容或错误；不锁定内部类形状、私有方法调用或数据字段排列。
- 主要验证 seam 为现有报告读取入口，使用临时目录内的真实元数据与材料文件。另保留必要的 Web 和收录高层测试，证明调用方实际接入共同读取 module。
- 复用已有报告目录、数据完整性、研究工具协同、周报及论文比较测试风格；不以单独测试抽取出的辅助函数替代真实调用验证。
- 重构前补齐行为刻画：同方向与跨方向、legacy 与专属方向、指定与未知版本、完整与摘要级质量、同级多报告、缺失 HTML、缺失 Markdown、缺失 PDF、截止时间内外。
- 专门构造生成时间与文件修改时间相反的报告，验证网页与 Markdown 读取仍按各自既有政策选择；对跨方向总览单独验证版本、质量及 HTML 修改时间政策。
- 显式选中旧报告时，断言最终收录内容确实来自该报告；报告缺失或版本不匹配时，断言既有错误且不改选其他报告。
- 通过先读取、再新增或删除材料、再执行新操作的场景验证无跨请求陈旧缓存。收录执行时仍覆盖材料失效后的实际结果。
- 必要时对目录枚举做窄范围观测，确认单次指定报告解析不重复发现同一目录；这仅验证明确的扫描复用目标，不把内部 helper 调用次数作为行为契约。
- 先运行受影响的定向测试，再按改动波及范围执行项目要求的回归检查。没有基准测量时不得声明页面速度或磁盘访问量的具体改善幅度。

## Out of Scope

- 统一各用途的报告排序或修改质量等级。
- 重构研究条件判断、论文按钮可用性或整个前端。
- 引入持久缓存、数据库索引、目录监视器、新后台任务或新的模型请求。
- 修改报告内容、重新生成历史报告、迁移用户数据或改变报告路径格式。
- 改变跨应用关联、同步回执、收录重试或个人笔记保护机制。
- 改变报告删除、发布事务、生成锁，或设计全新的文件一致性机制。
- 在本规格发布阶段实施代码重构。
