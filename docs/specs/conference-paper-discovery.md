# 会议论文回溯检索与三种推荐模式

## Problem Statement

研究者既需要追踪近期论文，也需要回溯指定会议已发表的相关工作。当前 PaperLoom 的论文发现与阅读围绕 arXiv 身份组织，缺少按多个会议及起止会议年份发现候选的能力。用户需要自行查看论文集、寻找 arXiv 版本，再纳入阅读流程。

在 arXiv 中搜索会议名称不能可靠证明正式录用，arXiv 投稿时间也不代表会议年份。扩大回溯天数或添加会议关键词不能满足这一需求。

## Solution

提供附加的会议回溯检索功能，同时支持独立手动探索与研究方向持续推荐。提供最新 arXiv、会议论文、混合推荐三种模式，默认沿用既有近期发现行为。

首批支持 ICML、NeurIPS、CVPR、ICLR、ACL；接受 NIPS 别名并覆盖历史届次。用户可多选会议，直接指定包含两端的起止会议年份。仅收录主会正式长文，第一版只让成功关联 arXiv 的论文进入现有推荐与阅读流程。

最新 arXiv 模式按既有投稿时间窗口追踪近期工作。会议论文模式严格限定会议、年份和论文类型。混合推荐模式将两类候选合并去重后按研究兴趣统一排序，不分配固定来源名额。

手动检索默认采用当前研究方向，允许临时主题或无主题浏览，不修改长期配置。研究方向保存的会议范围持续用于后续推荐，遵守现有历史去重和不相关排除规则，无需用户额外执行“导入候选池”。

## User Stories

1. As a 研究者, I want 在最新 arXiv、会议论文和混合推荐之间选择, so that 我能按追新或补读需求发现论文。
2. As a 已有用户, I want 未配置会议来源时保持现有近期发现行为, so that 升级不改变我的研究方向。
3. As a 研究者, I want 同时选择多个会议, so that 我能跨会议回溯同一研究问题。
4. As a 研究者, I want 首批选择 ICML、NeurIPS、CVPR、ICLR、ACL, so that 我能覆盖当前关注的会议。
5. As a 研究者, I want NIPS 与 NeurIPS 被识别为同一会议, so that 历史名称不会造成漏检或重复。
6. As a 研究者, I want 直接指定起止会议年份, so that 检索范围清晰且可重复。
7. As a 研究者, I want 起止年份包含两端且用于所有所选会议, so that 我能直观理解多会议检索范围。
8. As a 研究者, I want 无效会议或年份范围被校验, so that 错误配置不会启动检索。
9. As a 研究者, I want 按论文所属会议届次筛选, so that arXiv 上传年份不影响会议归属。
10. As a 研究者, I want 会议模式严格限定所选范围, so that 范围外候选不会补入结果。
11. As a 研究者, I want 只收录主会正式长文, so that 结果符合已明确的论文范围。
12. As a 研究者, I want 排除 Findings、Workshop、短文与 Demo, so that 伴随出版物不会被当作主会长文。
13. As a 研究者, I want 正式长文不因 Oral、Poster 或 Spotlight 被排除, so that 展示形式不会造成漏检。
14. As a 研究者, I want 查看会议名称、年份和归属依据, so that 我能核验结果。
15. As a 研究者, I want 第一版论文成功关联 arXiv, so that 我能继续使用现有阅读与报告能力。
16. As a 研究者, I want 不确定的关联不被当作成功匹配, so that 不同论文不会被误合并。
17. As a 研究者, I want 查看未关联 arXiv 的数量, so that 我知道结果的覆盖限制。
18. As a 研究者, I want 从独立入口手动检索, so that 临时探索无需修改研究方向。
19. As a 研究者, I want 默认采用当前研究方向, so that 不必重复输入研究兴趣。
20. As a 研究者, I want 输入临时研究主题, so that 探索新问题无需创建新方向。
21. As a 研究者, I want 不填主题也能浏览限定范围的论文, so that 我能直接探索目录。
22. As a 研究者, I want 临时查询不改变长期配置, so that 日常推荐仍遵循原有兴趣。
23. As a 研究者, I want 浏览不自动产生推荐或阅读记录, so that 查看与正式使用有明确区别。
24. As a 研究者, I want 主动收藏结果并进入现有阅读流程, so that 会议发现与阅读衔接。
25. As a 研究者, I want 保存模式、会议及年份到研究方向, so that 后续推荐复用这些条件。
26. As a 研究者, I want 持续挑选尚未推荐的相关会议论文, so that 我能逐步补读历史工作。
27. As a 研究者, I want 沿用现有已推荐和不相关排除规则, so that 不会反复看到已处理的论文。
28. As a 研究者, I want 没有合适候选时明确显示不足, so that 系统不会为凑数量越过检索范围。
29. As a 研究者, I want 混合模式独立应用两类时间条件, so that 历史会议论文不会被近期窗口排除。
30. As a 研究者, I want 同一论文只出现一次且保留全部来源, so that 结果简洁且可解释。
31. As a 研究者, I want 混合候选统一排序而不设配额, so that 优先阅读更相关的论文。
32. As a 研究者, I want 会议推荐遵守必要条件和明确排除条件, so that 新来源不会绕过主题边界。
33. As a 研究者, I want 查看进度并复用已取得结果, so that 多年检索不必每次从头处理。
34. As a 研究者, I want 区分失败、未关联、截断与零结果, so that 检索限制不会被误解为没有论文。
35. As a 研究者, I want 部分来源失败被清楚标明, so that 我能判断当前结果是否完整。
36. As a 研究者, I want 如实了解会议正式版本与 arXiv 修订版的关系, so that 不会误以为内容完全一致。
37. As a 维护者, I want 用固定目录和论文样本验证行为, so that 网络变化不会破坏常规测试的确定性。

## Implementation Decisions

### 1. 模式与来源分别表达

模式描述用户期望的候选范围，来源描述数据取得渠道。新增模式不复用现有 arXiv/alphaXiv 来源配置的枚举。最新 arXiv 模式沿用现有近期发现能力，保留既有 alphaXiv 配置行为。

会议范围采用稳定的会议身份和独立起止年份，不复用回溯天数。年份为整数且起始不大于结束，范围包含两端。会议模式与混合模式需选择受支持会议；尚未公布的目录不能报告为已成功检索但零结果。

### 2. 会议归属与论文类型

规范化五个会议身份及 NIPS/NeurIPS 别名。以正式论文集或可核验书目记录确认会议、届次与论文类型，不以 arXiv 会议关键词作为唯一中稿证据。

纳入主会正式长文，排除 Findings、Workshop、短文及 Demo。展示形式不决定是否纳入；类型或归属未知的记录不作为已核验长文进入正式会议候选。

### 3. 候选发现与 arXiv 关联

优先扩展现有 DiscoveryService 候选发现入口，在统一协调处实现三种模式、日期约束、来源状态与候选合并。会议目录读取及关联作为内部可替换依赖，纳入 ResearchClients 的生命周期与注入机制；调用方无需重复实现会议逻辑。

目录候选先核验范围与类型，再关联 arXiv。优先采用可核验标识或对应关系，标题相似不能独立证明同一论文；冲突与不确定关联不进入正式候选。PaperResolver 继续承担 arXiv 元数据取得与补全。

Paper 保持现有 arXiv 身份，新增可选的结构化会议归属、年份及证据信息，随序列化、存储和结果展示保留。旧论文记录仍可读。arXiv 关联不改变指定版本语义，也不意味着预印本与正式出版版本内容完全一致。

### 4. 时间、合并与排序

近期候选按 arXiv 投稿时间过滤，会议候选按会议年份过滤。合并后不能把所有候选统一套入近期日期窗口。

以规范化 arXiv 身份去重，保留全部发现来源及会议归属证据。合并后使用现有研究方向主题判定与排序，遵守必要条件和明确排除条件。不设置固定来源配额；同一批推荐可以全部来自某一类候选。

### 5. 手动探索与持续推荐

独立检索入口复用候选发现能力，支持当前研究方向、临时主题和无主题浏览；无主题浏览不凭空生成兴趣条件。查看结果不修改研究方向、阅读状态或已推荐历史。收藏及阅读通过既有显式操作完成。

研究方向持久化模式、会议和年份，后续推荐持续使用该范围。沿用既有已推荐去重、不相关排除及方向隔离规则；没有合适候选时不补入范围外论文。临时检索不改写长期配置。

### 6. 状态、预算与复用

沿用现有任务进度及来源状态机制，区分目录获取、关联成功、未关联、不确定关联、失败及截断。关联数量只针对实际取得的目录候选，不能把尚未取得的目录推断为全部未关联。

混合模式部分来源失败时可使用仍可用的候选并标记缺失；会议模式不得静默改为近期发现。部分结果不宣称完整覆盖。

按会议与年份复用目录及关联结果，保留来源与更新时间，避免每次推荐重复抓取全部历史范围。支持按需刷新；缓存有效期、具体候选预算和刷新调度由实现确定，并披露截断及过期对结果的影响。

具体目录提供方尚未选定，应逐会验证年份语义、主会长文区分、分页、覆盖和可用性。可采用会议正式论文集及 DBLP 等来源，不把尚未验证的接口视为已满足要求。

## Testing Decisions

测试只断言外部可观察行为，包括候选集合、来源与会议信息、错误状态、持久化配置和阅读状态，不绑定私有函数调用顺序、内部缓存布局或实现结构。

用户已确认主要通过现有 DiscoveryService.discover 验证三种模式、会议年份过滤、arXiv 关联与去重；通过现有 Web 和 DailyPipeline 对外流程补充验证配置保存、推荐历史与阅读状态。网络数据源采用固定样本和可注入适配器，常规测试不依赖实时网站。会议依赖位于统一发现入口内部，不为每层增加独立公共测试入口。

现有候选发现测试已经覆盖多来源合并、元数据补全、日期过滤和失败降级；研究方向编辑及草稿测试覆盖配置校验、持久化和只读预览；推荐控制测试覆盖收藏、不相关与状态隔离；客户端测试覆盖依赖注入、延迟创建和资源关闭。沿用这些测试先例。

验收场景：

1. 旧配置及未配置会议的研究方向保持既有行为，不访问会议目录。
2. ICML 与 ICLR、2022—2025 年只接纳范围内正式长文与成功 arXiv 关联，含两端年份。
3. NIPS 与 NeurIPS 归为同一会议，不产生重复候选。
4. 2021 年上传 arXiv、发表于 ICML 2022 的论文能命中 2022 年会议范围，即使超出近期窗口。
5. 近期上传但尚无指定会议归属的论文进入最新模式，不能进入会议模式。
6. Findings、Workshop、短文、Demo 与未知类型不进入正式会议候选；有效的 Oral、Poster、Spotlight 长文可进入。
7. 未关联、冲突及标题相似但不确定的记录不被伪装为成功候选，输出状态及数量可区分。
8. 同一论文同时命中两类发现时只出现一次，并保留全部来源、会议年份和依据。
9. 混合模式统一排序不强制配额，一类候选不足时不为凑数量放宽范围。
10. 会议来源遵守主题条件、不相关标记、历史去重和研究方向隔离。
11. 模式、会议和年份保存重载后保持一致；无效年份或不受支持会议不能形成有效配置。
12. 临时主题及无主题浏览不改变配置、收藏、阅读或已推荐记录；主动收藏沿用现有流程。
13. 失败、未公布、成功零结果、未关联和预算截断在输出中可区分，会议模式失败不返回近期候选充当会议结果。
14. 混合模式部分失败保留可用候选并披露缺失；复用数据保留范围、来源与更新时间。
15. 会议信息可序列化恢复，旧论文记录仍可读，既有 arXiv 指定版本语义不变。

真实目录的抽样联网核验与确定性测试分开记录，单次联网成功不能代替验收测试。

## Out of Scope

- 首批五个会议之外的任意会议、期刊或全量 CCF 目录检索。
- 未成功关联 arXiv 的论文进入推荐、收藏与阅读流程，以及全局论文身份改造。
- Findings、Workshop、短文、Demo 等论文类型扩展。
- 按展示形式、奖项、引用量或历史 CCF 等级变化筛选。
- 最新论文与会议论文固定推荐配额。
- 自动视会议正式版本和 arXiv 修订版为相同内容或替换指定版本。
- 宣称完整覆盖所有目录、关联和主题结果，或绕过来源访问限制。
- 改变 Zotero、Obsidian 协作职责或跨应用同步行为。

## Further Notes

本规格由 2026-10-01 的设计讨论综合形成，用户已确认产品规则和测试入口。本次请求生成规格，不实施功能。

项目已配置使用 Dennis-Huangm/PaperLoom 的 GitHub Issues 及默认 triage 标签。本规格按 to-spec 发布为 issue，并使用 `ready-for-agent` 标签。

本期保持 arXiv 身份是可分期调整的范围选择，尚不足以形成难以逆转的架构决定，因此不单独创建 ADR。会议分类标签应按明确版本的 CCF 官方目录核验，不能用会议名单代替分类证据。
