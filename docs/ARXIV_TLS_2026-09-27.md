# arXiv HTTP 406：TLS 连接配置与缓存差异

已定位一个可以在本机重复验证的客户端触发条件：同一查询、同一进程、相同 HTTP 代理和请求头，HTTPX 默认 TLS 配置在缓存未命中的请求上返回空正文 406；只启用 TLS 1.3 `post_handshake_auth` 后，相同请求返回 200，且响应显示缓存未命中。正式 `ArxivClient` 已采用该兼容设置。

这不是“arXiv API 整体不可用”，也没有证据说明用户的 Clash 出口配置错误。服务端具体是 CDN 规则、TLS 特征识别还是其他入口逻辑，缺少服务端日志，不能进一步断言。HTTP 406 本身也不是 TLS 握手失败：连接已建立，上游随后返回了 HTTP 拒绝响应。

## 为什么 curl 正常，项目却失败

项目每次检索的日期窗口包含当前分钟，容易形成新的 URL。固定的 electron 测试 URL 则已有可命中的缓存。实际对照中：

| 对照 | HTTP 结果 | 缓存信号 |
| --- | --- | --- |
| 原始组合查询，HTTPX 连续两次 | 406，空正文 | `MISS, MISS` |
| 固定 electron 查询 | 200，Atom 正文 | 含 `HIT` |
| 同一组合 URL，显式相同代理与请求头，先用 HTTPX | 406 | `MISS, MISS` |
| 接着用 curl 请求同一 URL | 200 | `MISS, MISS, MISS` |
| 再用 HTTPX 请求同一 URL | 200，正文哈希与 curl 一致 | 含 `HIT`，Age 为 3 秒 |

因此，curl 成功后再测 Python，有时会产生“自己恢复了”的表象；缓存已经被成功请求填充。这比将前几轮结果简单归结为随机网络波动更能解释观察到的现象。

## 排除与最小化实验

所有请求顺序执行并间隔至少 3 秒，不发送用户凭据到 arXiv、不改 Clash 规则、不使用并发压力或无限重试。

1. 固定查询时间和 URL，成功/失败证据保存在 `work/arxiv-fixed-probe-20260927/baseline.json`。
2. 去除关键词、去除日期、仅保留类别等查询仍出现 406，不能归因于组合语法复杂度。
3. 同义 URL 的不同编码或参数顺序也可能得到不同缓存命中结果，因此不能仅凭某个编码变体成功就改写查询格式。
4. 显式让 Python 与 curl 使用同一 HTTP 代理，统一 User-Agent、Accept 与 Accept-Encoding。再移除 Connection 或改为 close，HTTPX 仍返回 406。
5. 同一 Python 进程中，`requests` 成功处理尚未缓存的同一 URL；因此不是 Python 进程整体不能访问，也无需改用 curl 子进程。
6. 保持 HTTPX、代理、URL、HTTP 请求头不变，仅替换 TLS 上下文为 urllib3 的配置，新请求从 406 变为 200。
7. 分别单独切换 TLS 选项：开启 `post_handshake_auth`、或关闭 session tickets，两者在各自独立的新 URL 对照中均使 406 变为未命中缓存的 200。说明这里影响的是连接特征，不能宣称服务端“必须进行客户端证书认证”。最终只采用前一个标准兼容设置。

只读查看 Clash 配置时，发现 `export.arxiv.org` 的独立域名规则和 select 类型分组，该规则之前没有 PROCESS 规则。没有修改配置，也没有把未获取到的控制器状态当作实时路由证明。同进程、同代理的 TLS 单变量对照才是主要因果证据。

## 生产修复

`ArxivClient.__init__` 使用公开的 `httpx.create_ssl_context()` 建立原有验证上下文，在支持 TLS 1.3 时设置 `post_handshake_auth=True`，再传入自身 HTTPX 客户端。

- 保留证书与主机名验证，以及 `SSL_CERT_FILE` / `SSL_CERT_DIR` 的既有行为。
- 没有修改代理、HTTP 请求头、日期范围、类别、关键词、排序、结果上限、重试和限速规则。
- 不修改其他 HTTPX 客户端，不影响 LLM、元数据核验等服务的连接配置。
- 不新增 curl 或 requests 生产依赖，不依赖预热缓存，不以增加 406 重试掩盖问题。

Python 标准库的 `HTTPSConnection` 从 Python 3.8 起就在默认上下文中启用这个 TLS 能力；参考 [Python 官方说明](https://docs.python.org/3.13/library/http.client.html#http.client.HTTPSConnection)。查询和三秒间隔遵循 [arXiv API 手册](https://info.arxiv.org/help/api/user-manual.html)。这两份文档解释配置与 API 用法，不构成 arXiv 内部拦截规则的证据。
