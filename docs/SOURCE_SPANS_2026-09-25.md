# 原文片段引用与基础元数据保护

2026-09-25。本阶段承接真实报告再生成中发现的摘录抄写失败和作者姓名错误，已实现程序生成的原文片段 ID、确定性的基础信息表，以及与原有引用、数值校验、任务恢复和比较证据的兼容。

## 行为变化

`source_spans.py` 从解析器提供的 PDF 物理页面文本生成版本化片段。每段不跨页，最多 500 个原始字符，相邻片段重叠 100 字符以减少短句和表格行在边界断开；只有至少 20 个非空白字符的片段才进入索引。ID 包含索引格式版本、整份页面文本 SHA-256 的前 24 位、物理页和字符起止位置。页面文本、顺序或解析结果变化会使旧 ID 失效。

分片模型同时收到原有解析正文和独立 PDF 片段清单，优先输出 `[[证据ID:实际ID]]`。两种文本的分片边界不一定一致，提示明确要求同时提取，不把 Markdown 偏移当作 PDF 页码。程序只将该分片收到的有效 ID 向后传递，整合时按 ID 重新取回准确原文，不依赖模型再次拼写。整合原文预算为 32,000 个字符；超额或未知 ID 替换为证据不可用提示，不能伪装成仍有依据。

定稿时再根据当前页面文本重建索引，生成原文链接与摘录。`evidence.json` 中的已引用片段保留 ID、页码、字符范围和完整页面文本哈希。重复出现在多页的内容可以通过指定页面的合法 ID 引用；旧式 `[[证据:逐字摘录]]` 仍保持 20–600 个非空白字符、唯一物理页面匹配的规则，不使用模糊匹配。未知、过期、摘要级或无 PDF 的 ID 均不能生成可信页码链接。

数值审核使用程序取回的同段/同行原文；不把 ID 中的数字当成实验结果。编号式三级及以下标题也不计为实验数字。错误数值、无原文依据的比例计算仍会提示待核对。片段可能同时含相邻模型的数据，**数值出现仍不证明模型、指标或因果归属正确**，没有增加自动语义核验。

比较服务继续使用已定位摘录作为原始证据，并在新建的固定快照中保留片段 ID、偏移和文本哈希。旧报告和旧比较不自动改写。已有恢复缓存依据实际提示词签名复用；新 ID 清单进入签名，改变页面文本不会复用旧 ID 的分片响应。无需迁移旧数据格式。

## 元数据保护范围

`report_metadata.py` 在模型生成后重建基础信息表：

- 英文标题、作者姓名、arXiv ID/版本/类别、首次公开与修订日期取自论文快照；作者姓名优先使用 arXiv 等发现来源保存的拼写，缺失才回退到核验元数据。
- 会议、状态、DOI、正式发表日期等使用现有结构化核验结果；缺失则为未核实，不让模型猜测。
- 不按作者序号或近似姓名自动连接机构。结构化机构独立列出；模型从原文抽取的单独机构行保留为“机构（论文摘录，未核实）”。合并了作者与机构的模型行不用于覆盖结构化姓名。
- 中文译名仍由模型提供。正文中的姓名和学术陈述不由本模块重写。

这能阻止模型把正确的 `Marek Kadlčík` 改为 `Marek K駆lcík`，但不能修正输入元数据自身的错误。元数据日期、出版状态是否真实仍取决于原有核验来源，不能把“由程序生成”理解为“事实已经独立确认”。

## 开销与限制

为了保持 Docling 等解析正文提供的结构，同时提供可靠页内原文，分片输入会增加一份片段材料，存在约束内的重复文本。索引材料较长时会增加分片数；本次 VectorEdits 从原来的 1 个分片变为 2 个，因此报告请求从 2 次变成 3 次。现有请求预算继续约束实际调用，真实评估脚本也按新分片计划计算所需请求。整合片段材料限制在 32,000 个原文字符以内。

本阶段交付时尚未真实再生成 SVGenius 等长论文；后续已完成 19 页 SVGenius 的生成与针对性审阅，发现并修复整合预算挤掉后半篇引用的问题，见 [长文引用预算验证](LONG_REPORT_QUALITY_2026-09-26.md)。扫描件依旧需要可提取页面文字；公式符号提取错误、跨片段语义、表格列归属和过宽概括都不会因使用 ID 自动消失。片段哈希是所提取页面文本的身份标识，不是 PDF 文件哈希，也不是内容真实性证明。
