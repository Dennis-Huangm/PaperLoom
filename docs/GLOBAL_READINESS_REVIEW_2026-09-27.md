## 发现与处理

### P2：出版信息可能产生错误的确定性表述（已修复）

- Semantic Scholar 返回无会议信息、arXiv/CoRR 时，原代码仍接收 `publicationDate`，报告会把预印本日期写成“正式发表日期”。会议信息冲突时，也可能保留来源 A 的会议信息却写入来源 B 的日期。
- 同一合并过程可用 `10.48550/arxiv.*` 预印本 DOI 覆盖已有正式 DOI。
- 评论仅包含 `Submitted to CVPR`、`Under review at ICLR`、`Not accepted to ICML`，或提及旧论文时，也会被识别为该论文的发表声明。

修复：只在接受非预印本会议信息的分支补充日期，已有日期优先保留；预印本 DOI 不覆盖出版 DOI；评论只采用明确的正面发表声明或完整的简短会议公告，排除投稿、审稿、拒稿等语境。外部元数据仍可能存在自身错误，保留来源与冲突提示。

涉及 `metadata.py` 公共核验入口；报告基础信息表的回归用例直接经过 `protect_metadata()`。对既有报告与保存的元数据不做静默批量改写。

### P2：本机 HTTP 访问边界检查不完整（已修复）

- 外部域名 Host 请求可以读取本地设置、任务页面和静态内容。只绑定 loopback 无法阻止这类请求进入应用，是 DNS 重绑定防护缺口。
- 修改请求只在解析到外部 hostname 时拒绝，`Origin: null` 可以绕过这一检查；畸形 IPv6 Origin 则会抛出异常。

修复：对全部请求验证本机 Host；对修改请求验证 Origin 的协议和主机，拒绝不透明/非法来源及跨站请求。保留无 Origin 的本机 CLI 客户端用法，以及 localhost、IPv4/IPv6 loopback；`testserver` 供现有测试使用。测试确认正常本机访问仍通畅。

证据为离线 HTTP 接口复现，未实施真实浏览器 DNS 重绑定攻击。该改动没有加入多用户登录功能；自定义域名反向代理不属于本机使用范围。
