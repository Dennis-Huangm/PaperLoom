# GUI 任务持久化与中断恢复验收

日期：2026-09-24。独立数据目录 `work/recovery-ui-x1m1mhcv`，本地服务 127.0.0.1:8770。使用假论文和关闭模型的周报生成；邮件、Zotero、Obsidian 均关闭，未修改真实研究数据。

验收过程与结果：

- 在独立子进程创建两个周报任务：一个运行到活动归纳并记录警告，另一个仍排队；通过直接退出进程模拟未执行清理的中断。
- 启动 GUI 后两个任务均显示“已中断”，保留原提交内容、运行进度说明和警告；页面提供“重新执行”，启动本身不执行任务。
- 分别点击恢复，创建两条关联的新记录。两次均成功生成周报，原任务显示“已创建恢复任务”，原警告和中断说明保留。
- 强制终止此次隔离 GUI 服务进程，再使用同一数据目录重新启动。刷新后仍有两条成功记录和两条原中断记录；恢复按钮不会重新出现，两个结果链接保持不变。
- 打开成功结果，显示本期活动、固定 v2 论文和原统计截止时间；模型关闭时仍能生成本地活动周报。
- 桌面任务卡片正常显示状态、提交内容、恢复来源、时间和结果入口。390px 视口下卡片换行、按钮可读，无横向页面溢出（内容宽度和滚动宽度均为 375px）。
- 浏览器错误日志为空。验收后恢复视口、关闭临时标签页与服务。

自动化测试另覆盖：真实子进程退出释放锁、活动/排队请求持久化、不自动恢复、关闭时锁的生命周期、磁盘写入失败不调度、损坏记录保留、原配置和论文版本恢复、重复恢复及关联断点修复、环境密钥不进入快照、恢复推荐不发邮件、各任务执行参数、跨方向请求拒绝、任务台账下载保护与历史分页。

最后补充了周报恢复的时间边界回归：原统计截止时间不变，`generated_at` 使用实际生成时间，避免较晚恢复的周报在列表和 Obsidian 导出中被错误排序。

另补充并发回归：旧版本报告恢复不与新提交的“查询最新版”任务合并；浏览器布局不受该队列标识修正影响。

最终全量回归：**300 passed，1 warning，50.25s**，日志 `work/recovery-final-tests.log`。唯一 warning 是测试框架弃用提示。Python 编译、JavaScript 语法、依赖与差异格式检查通过。
