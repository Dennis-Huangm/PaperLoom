# 真实论文报告与跨论文比较：小规模验收

后续进展：本篇保留第一轮审查记录；更新提示词后的实际报告生成与比较结果已另存于 [再生成验收](QUALITY_REGENERATION_2026-09-25.md)，包含成功改善项与仍未解决的问题。

日期：2026-09-25。范围为 5 篇已有报告的重点原文核对，以及 2 组真实模型比较。由 Codex 对照本地固定 PDF 逐项审阅，不是独立人工盲测，也不是模型准确率评测。未改写原始研究资料；桌面与窄屏界面验收仍延期。

## 主要发现

历史报告在抽查的大多数实验表格和公式上保留了正确内容，但存在影响阅读判断的具体问题：表格行合并造成错误数字、把处理片段编号当作页码、分片笔记丢失脚注/附录信息，以及概括实验结论时遗漏指标范围。

真实比较也会继承历史报告错误。此次模型照抄了 SVGEditBench 报告的 `0.8971`；现有原文数值检查将其拦下，最终矩阵没有发布该数值结论。另一方面，历史报告没有已定位原文摘录，导致许多实际上能从 PDF 查到的实验数字仍无法进入比较。这是当前证据输入的限制，不能通过把模型报告当成原文来消除。

## 样本与版本

| 论文 | 固定修订版 | PDF 页数 | 重点 |
| --- | --- | ---: | --- |
| SVGEditBench V2 | 2502.19453v1 | 17 | 表格行列、基线与资源链接 |
| SVGenius | 2506.03139v1 | 19 | 多任务指标、长文附录公式、出处 |
| VectorEdits | 2506.15903v1 | 5 | 完整实验表、指标例外、脚注链接 |
| EdiVal-Agent | 2509.13399v3 | 47 | 多轮指标、长附录、原文内部不一致 |
| SVG-Score | 2609.03806v1 | 26 | 奖励公式、训练参数、人工一致性 |

以上版本号均在 PDF 提取文本中找到对应 arXiv 水印。每份 PDF、报告及元数据均保存 SHA-256。历史产物没有记录模型和提示词版本，因此不能把本次发现归因于某个已知模型，也不能声称这是更新前后同模型的对照试验。

对 30 项有意选择的检查点，17 项与原文相符，10 项有信息遗漏，另有 1 项数值/行归属错误、1 项出处错误和 1 项概括范围过宽。这个分母不是随机抽样，也没有穷尽各报告的陈述，**不换算成准确率**。逐项记录与文件哈希见 [报告核对记录](quality/2026-09-25-real-reports.json)。

## 具体问题与正确读法

| 样本 | 历史报告问题 | 原文核对与影响 |
| --- | --- | --- |
| SVGEditBench | 将 `Original Ground Truth` 写成一行，DINO 写成 `0.8971` | 物理第 5 页 Table 1 有 Original 和 Ground Truth 两行；Original 的 DINO 为 `0.897`。不能将相邻行的 `1` 拼到前一个数值 |
| SVGEditBench | 称材料没有仓库 URL | 第 7 页 A.2 给出 `github.com/mti-lab/SVGEditBenchV2`，网址跨行；应保留作者提供的入口，是否可下载另行核验 |
| SVGenius | Table 8 标为“第 5/9 页” | PDF 有 19 页，Table 8 在物理第 10 页。处理分片数不等于页数 |
| SVGenius | 未保留 CCR/rMSE 公式 | 第 18–19 页 G.2/G.3 给出公式 (2)/(3)。提取失败应写“当前材料未能确认”，不能扩大为原文未提供 |
| VectorEdits | 总结称“全部被不编辑基线超过” | 第 4 页 Table 2 中 no-edit 在 CLIP/DINOv2 上领先，但 GPT-4o mini、Llama 4 Maverick 的 MSE 更低。正文虽提到例外，一句话总结仍过宽 |
| VectorEdits | 称没有数据集具体 URL | 第 1 页脚注明确给出 Hugging Face 数据集路径。机构也在首页列出，应区分论文自述与外部核验 |
| EdiVal-Agent | 对提示词提供情况概括不足 | 第 30–33 页附录 M 提供对象发现、指令生成等提示词；不能笼统描述为未提供完整提示词 |
| SVG-Score | 称资源入口及商业生成 prompt 未提供 | 第 1 页有项目入口与资源公开声明；第 15 页 B.3 展示 System/User Prompt。是否能下载资源未在线验证 |

也记录了通过项：SVGenius 的 PQA 最优数值与模型归属、VectorEdits 的结果表、EdiVal 的 Image Success Rate（没有混用 Overall Task Rate）、SVG-Score 的 ordinal/ranking reward 公式与训练超参数。EdiVal 报告正确保留了原文中的 13/16 个模型、Qwen2/Qwen2.5 命名冲突。

表格与公式相关页使用 Poppler 渲染并直接检查；其余项目对照 PDF 页面文本和报告。此次没有开展 OCR、图示解释完整性或全部数学推导审计。

## 真实模型调用与比较结果

初次使用项目原配置请求短论文报告，2 次请求均以 `APITimeoutError` 结束，没有返回可评分内容。失败与超时记录保留，未算作成功报告。

用户随后指定了新的服务地址和 `gemini-3.8-flash-high`。最小请求约 7.41 秒返回 `OK`，两组比较再各用 1 次请求，均成功完成；服务返回的模型标识均为 `gemini-3.8-flash`。这是服务声明的模型标识，未独立验证其底层实现。新配置共使用 3 次请求，整个阶段含旧配置失败请求共 5 次。

密钥仅传入调用进程，不保存到项目 `.env`、配置、脚本、提示词记录或评估文档。项目默认模型没有更改。

比较使用生产 `ComparisonService.prepare()` 与 `generate()`。为了在同一评估方向核对历史文件，仅给独立副本赋予 `quality-evaluation` 方向；原始方向和文件不变，不伪造历史质量字段，不手工注入 PDF 摘录，不把个人笔记提供给模型。

| 组别 | 比较对象 | 最终保留 | 待核对 | 主要原因 |
| --- | --- | ---: | ---: | --- |
| A | SVGEditBench V2 / VectorEdits | 6 / 14 | 8 / 14 | 3 项仅报告数值、3 项原文数值不足、2 项摘录不符 |
| B | EdiVal-Agent / SVG-Score | 8 / 14 | 6 / 14 | 1 项仅报告数值、4 项原文数值不足、1 项摘录不符 |

这些是规则保留数量，**不代表正确率，也不能把全部拒绝项称为模型事实错误**。例如 EdiVal 的长摘要摘录超过支持摘录长度上限，属于格式问题；许多正确实验数字只存在于模型报告中，属于原始依据缺失。模型还会在支持摘录中删除 Markdown 标记，导致其不再是所引材料的逐字片段。

逐格对照发现：两组都保留了任务定义差异，没有产生跨论文胜负排名；组 A 的模型回答明确保留了 VectorEdits 的 MSE 例外，但该格仍因数值缺少原文支持而被保守拒绝。非数值语义仍未自动核验，部分条目的支持摘录并未覆盖描述中的全部细节，不能以“引用存在”代替语义判断。

真实输出还暴露了来源标签问题：组 A 两个方法单元格同时使用摘要与模型报告，却统一记录为 `primary_excerpt`。现已改为 `mixed_sources`，显示“推断（混合原文与模型报告）”。对已保存原始响应离线重放后，保留/拒绝数不变，仅这两格的来源标签变化。原始生成产物不覆盖，另存 reviewed 版本。

模型响应哈希、请求配置、服务返回模型名及重放结果见 [比较验收记录](quality/2026-09-25-real-comparisons.json)。完整请求、响应、输入快照和 PDF 副本位于 `work/real-quality-live-20260925/`。

## 已实施的改进

1. 报告整合直接接收最多 5,000 字符的原始首页和最多 12 段、每段最多 500 字符的链接上下文，绕过分片摘要的信息损失；不自动访问链接，也不把参考文献链接自动认定为本论文资源。
2. 元数据提示补入实际 arXiv 类别与修订版；论文首页的机构/资源声明要求注明来源，区别于外部核验。
3. 分片与整合提示明确保留附录指标公式、脚注资源、表格行列/单位/缩放因子、指标范围和反例，禁止把内部片段编号当作页码。
4. 比较同时引用原文与模型报告时统一归入推断并标明混合来源；数值仍必须由所引原始材料支持。
5. 比较提示要求短而逐字的支持摘录；只有二手数值时优先保留有依据的定性描述，避免把数字硬塞进单元格后整格被拒绝。

没有放宽数值检查，也没有声称完成自动语义核验。报告提示改进和最终比较提示改进已完成代码/回归验证，**尚未用更新后的全部提示词重新生成报告或比较来测量收益**；本次可确认的线上结果是两组已保存比较，标签修复则经过离线重放验证。

## 复现与验证

默认只创建独立副本和哈希清单，不调用模型：

```bash
python scripts/evaluate_real_quality.py --source run --output work/real-review-new
```

需要真实调用时显式加 `--live`；凭据先由操作者设置到指定环境变量，不放在命令或文件中。示例仅比较、不重生成单篇报告：

```bash
python scripts/evaluate_real_quality.py --source run --output work/real-review-live-new --live --comparisons-only --model gemini-3.8-flash-high --api-key-env PAPERLOOM_EVAL_API_KEY --base-url-env PAPERLOOM_EVAL_BASE_URL --max-requests 2
```

输出目录必须是新的、位于源资料目录之外的目录。默认最多 5 次实际请求，兼容重试也计入；不会修改默认配置、运行发现流程、发送邮件或调用 Zotero/Obsidian。`--live` 未加时不会加载密钥或请求服务。源 PDF 和历史报告不纳入仓库测试夹具；离线回归只使用最小事实摘录。

最终全量回归 **417 passed，1 warning，59.19s**，日志 `work/real-quality-final-tests.log`。新增 7 项回归覆盖原文材料跨分片摘要保留、链接/上下文上限、真实表格小数错误、概括范围的语义检查边界、混合来源降级及数值不放宽。Python 编译、JavaScript 语法、依赖一致性和差异空白检查通过。唯一 warning 仍是已有 Starlette TestClient/httpx 弃用提示。

原始 15 个文件（5 组 PDF/报告/元数据）哈希复核一致，没有改写历史成果、安装系统任务或执行外部同步。
