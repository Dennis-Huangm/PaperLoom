# 表格数值归属与依据不足时的自动处理

本批承接桌面与窄屏验收后的内容质量优先项：让正式生成流程发现可识别的模型/指标归属错误，并自动处理缺少数值依据的内容。处理使用本地原文与已生成文本，不增加模型调用。旧报告不自动改写。

## 正式流程

`DailyPipeline._process_paper` → 结构整理 → `attach_evidence` → 数值/表格检查 → 自动处理 → 引用替换 → 保存 Markdown、JSON、HTML → 可选 Obsidian 导出。

- 保留 v2 同段/同行的数值、单位出现检查，范围仍为“实验设置、关键结果、可复现性”。
- 表格可沿已验证引用检查同页原文中的模型行。支持明确分隔的数字，按原始顺序选择列；可以省略 RLD 等列，不能把同页其他模型的数值移过来或交换数值顺序。
- 唯一的平面表头可按名称绑定指标列，允许正确重排列顺序；对照单位、方向与缩放标记。来源列头明确给出的 `%` 可以用于本列数值，不推断比率换算或其他单位转换。
- 原文 pipe 表中明确列出的 Dataset、Split、Task、Setting 等条件须一致；纯文本难度行仅识别明确的 Easy/Medium/Med./Hard 标签，不自动建立别名。
- 只使用所引页面，候选行必须与引用范围相交。旧式连续摘录没有原始偏移时，要求完整行位于摘录内。可从相交范围取回完整原始行/平面表头，引用 ID、原文摘录及 PDF 页码不改变。

## 自动处理

- 确认有问题的表格单元格显示“—”，其余单元格、列结构和引用保留。“—”仅表示暂不展示，不表示零、缺测或论文没有报告。
- 普通定量段落缺少依据时暂不展示该段，不将它重写为可能同样不成立的定性结论。连续的无来源列表项可合并为一条短提示。
- `evidence.json` 中 `numeric_audit.version=3` 保存完整原始块、精确字符范围、替换后内容、原因、表格检查级别及保留/隐藏统计。渲染前检查原始块一致性，拒绝将过期结果应用于其他文本。
- 报告正文不再增加逐条长解释，只在开头和“引用与核对”中提供简短提示及详情入口。任务警告与报告库继续显示待核对状态。
- 不仅因为解析器无法确定表头/别名而整表清空；这类结果记录为未核验，并在报告末尾说明。缺少可定位摘录、数字/单位不在所引材料中或明确归属冲突，才触发自动隐藏。

检查级别：

| 状态 | 实际含义 |
| --- | --- |
| `headers_checked` | 当前可识别的标量单元格均可与明确的源表头/行对应；不代表复杂公式或一般语义正确 |
| `partial_headers_checked` | 仅部分指标列可对应，其余仍需核对 |
| `row_order_checked` | 同一模型行与数值顺序匹配，未证明多级表头归属、单位或实验可比性 |
| `unassessed` | 行、表形或上下文无法可靠识别；不是通过 |
| `mismatch` | 发现可明确指出的数值、顺序、列或条件冲突 |
